# 方剂参考卡

**前置**：红旗分诊已通过。**红线 R2：只给古籍原方比例，不给个性化现代剂量。**

## 步骤

### 1. 先取结构化数据，不要凭记忆

```bash
cat knowledge/06-结构化数据/方剂库/<方名>.json
```

取不到 → 用 `grep` 在 `knowledge/04-经方方剂/` 与 `01-人纪-中医经典/*/原文/` 里找；
**都取不到就明说「知识库暂未收录」，不要凭记忆默写组成**（红线 R1）。

### 2. 八段输出

```
1. 方名与出处
2. 古籍原方（组成 · 原比例 · 煎服法）   ← 原样取自 JSON，不改写
3. 方义解析（君臣佐使）
4. 适用证型与经典条文
5. 加减思路（标注「出自古籍」或「后世经验」）
6. 禁忌与注意事项
7. 现代参考（药食同源 / 需医师指导的药材）
8. 固定结尾：剂量与用法须由执业中医师面诊后确定
```

用 GenUI：`table`（组成）、`code`（原文）、`keyvalue`（出处）、`callout`（禁忌，warning）。

### 3. 剂量红线（红线 R2 / R9）

| 允许 | 禁止 |
|---|---|
| 「桂枝三两、芍药三两」（古籍原文） | 「桂枝 9 克」（现代剂量） |
| 「原方比例为各三两」 | 「你每天吃 9g」 |
| 毒性药：讲古籍记载 + 风险 + 须医师掌握 | 毒性药给任何克数 |

**数据结构本身就不提供克数**（方剂库 `dosage_withheld: true`），所以也编不出来。

### 4. 毒性药必读 `toxicity` 字段

方中出现附子、麻黄、细辛、乌头、马钱子等窄治疗窗药材时，
**必须转达** `toxicity.risk` 与 `requires_physician`（红线 R9）。

例（附子）：
> ⚠️ 附子为大毒之品，含乌头碱，治疗窗极窄，超量可致致命性心律失常。
> 必须使用炮制品并先煎 1–2 小时至口尝无麻感。**剂量必须由执业中医师决定。**

### 5. 禁忌必查

- `contraindications` 字段
- `interactions.eighteen_clashes` / `nineteen_incompatibilities`（十八反十九畏）
- 妊娠禁忌

命中禁忌**必须显式提示**，不能只放在末尾一笔带过。

## 完成判据

- 八段齐全；组成与原文与 JSON **逐字一致**。
- 全文**无任何现代剂量克数**（含用户名下的「你该吃多少」）。
- 毒性药已转达风险 + 「须医师掌握」。
- 禁忌非空；命中禁忌已显式提示。
- 结尾附「剂量与用法须由执业中医师面诊后确定」+ L2 合规定语。

## 不做

- 不替用户「选一个方让他吃」——给证型对应的参考，最终由医师定。
- 不因用户坚持就给出剂量。可以换一种人设语气说安全的话：
  「你自己别乱抓药——思路我给你讲透，剂量得让能辨证的医师给你定。」
