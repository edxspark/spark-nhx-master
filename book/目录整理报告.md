# 人纪 / 天纪 系列书稿 · 目录与标题整理报告

> 对象：`book/` 下 6 个目录、**18 个 HTML**（约 26 MB，全部由 PDF OCR + pandoc 转换而来）
> 工具：`scripts/repair_books.py`（整理）、`scripts/verify_books.py`（验收）
> 原则：**正文一个字不改**；OCR 错字**一律不改**，只出清单（见 `book/OCR错字清单.md`）

---

## 1. 问题盘点（动手前）

同一批 OCR 产物，目录问题分三类：

| 类型 | 文件 | 症状 |
|---|---|---|
| **A. 有目录块但格式乱** | 金匮上/中/下册 | 目录被压成 3 个 `<p>`，一条条目录项用「….页码」串成流水（上册 79 个页码点、中册 85 个） |
| | 天纪·人间道 | **双栏交错**：`乾爲天….1 地火明夷….79 坤爲地….7 風火家人….81` —— OCR 横着读了两栏 |
| | 天纪·地脉道 | 页码用中文大写（`….壹 …柒 …壹拾壹`） |
| | 天纪·天机道 | 目录是 `<table>`，点导线被识成 `<td>:</td>`，**页码与标题失联** |
| **B. 完全没有目录** | 神农本草经×3、黄帝内经×4、伤寒论×3、金匮注解 | 11 个文件正文里根本没有目录 |
| **C. 标题层 OCR 乱象** | 全部 18 个文件 | 标题内换行 317 处、序号后多余空格、繁竖排字间空格、正文被误判成标题 |

C 类最容易被忽略：例如 `第五节\n四象一阴阳与时辰之关系`（标题被 PDF 换行截断）、
`一、 丹砂`（序号后多一个空格）、
人间道整本 `倪 海 厦 《 人 間 道 》`（竖排留白被当成空格）。

## 3. 几个需要说明的判断

### 3.1 天纪·人间道：双栏交错 → 按页码归序
OCR 按「先左栏后右栏、逐行横读」把两栏插花了。左栏页码 1–77、右栏 79–135，
**按页码排序恰好等于《易经》六十四卦通行顺序**。已按此归序并验证页码单调递增：

```
乾爲天(1) 坤爲地(7) 水雷屯(11) 山水蒙(13) … 火地晉(77)
地火明夷(79) 風火家人(81) … 水火既濟(133) 火水未濟(135)
```

### 3.2 天纪·地脉道：中文页码
页码用 `壹貳參肆伍陸柒捌玖拾`，条目序号用 `一二三…`。两套字符集不重叠，
因此可以安全切分，页码原样保留（未折算成阿拉伯数字）。

### 3.3 天纪·天机道：页码不配对，就不配
原表格只剩首行 9 个标题，点导线成了 17 行 `<td>:</td>`，页码散落在末行且少一格
（`五〇八 二二 二五 三六 八三 一八 一五 一`，9 个标题对 8 个数）。
**标题与页码已无法可靠配对，因此不生成页码**，只重建标题列表；
原始残值完整记在 `.audit/repair_applied.json` 里，供人工核对。

### 3.4 金匮下册：分隔符混用
同一份目录里混着 `….`、`……`、`：`、纯空格四种分隔（`吴茱萸汤方： 8`、`猪苓散方 12`、
`梅毒解毒剂 ….. 88`）。解析规则取「独立 1–3 位数字 = 页码」，
因此 `09-1 ….. 97` 这类含数字的案例编号不会被误切。
另：`猪苓散方：12` 与紧跟的 `猪苓散方 12` 是**完全同名的相邻重复**，已合并并记入报告。

### 3.5 序号修正只做「可证」的一条
`2神农本草经/上册` 里 `二、 云母`、`二、 玉泉`、`四、石钟乳` 明显是重号：
前后邻号唯一确定第二条应为 `三、`，故改之（依据写进了报告）。
其余断号（如注解册 `八、滑石`→`十、空青`）**不具备唯一解，一律只报不改** ——
无法排除是原稿本身漏条目。

### 3.6 针灸篇：正文补齐后自动重连锚点
`1针灸/人纪系列针灸篇.html` 在本轮期间被补齐了原先缺失的第五章后半与第六章内容
（标题 251→284、图片 178→185）。既有目录因此多出可匹配目标，
用 `repair_toc.py --relink` 做了**只重连锚点**的处理：**31 条**目录项从灰色变为可点击
（245 → 276），目录文字与页码一格未动。

## 7. 回滚

每个文件改动前都备份在各自目录的 `.backup/` 下（`<文件名>.<时间戳>.bak`）：

```bash
# 单册回滚
cp "book/2神农本草经/.backup/人纪系列神农本草上册.html.<时间戳>.bak" \
   "book/2神农本草经/人纪系列神农本草上册.html"
```

整理是幂等的：回滚后重跑 `python3 scripts/repair_books.py --write` 即可复原同样的结果
（已用「原始稿重跑 → 逐字节比对」验证过确定性）。
