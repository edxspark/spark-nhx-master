# 来源台账（Source Ledger）

> **用途**：逐项记录每份入库内容的来源、获取时间与授权状态。
> **维护约定**：每次采集后立即登记；状态变更时更新本表并注明日期。

---

## 1. 状态定义

| 状态 | 含义 | 可否对外提供 |
|---|---|---|
| `公有领域` | 著作权保护期已届满或不受保护 | ✅ 可 |
| `主张公开` | **项目决策方判定为公开资源**；见 §2.2 决策记录 | ✅ 可（决策方承担风险） |
| `已授权` | 已取得权利人书面授权 | ✅ 可（按授权范围） |
| `合理使用` | 限于评论、教学、研究目的的有限引用 | ⚠️ 仅限引用 |
| `待授权` | 权属未确认或授权未取得 | ⏸ 暂停对外 |
| `禁止使用` | 已确认不可用 | ⛔ 禁止 |

---

## 2. 决策记录与证据

### 2.1 关于「公开资源」的事实说明

**必须区分两个概念**（这不影响决策，只影响风险认知）：

| 概念 | 含义 |
|---|---|
| **公开可访问** | 任何人都能在网上看到 |
| **无版权 / 公有领域** | 著作权保护期届满，法律上不受保护 |

公开可访问的内容**仍然受著作权保护**。汉唐官网自身也明确声明了保留权利：

| 证据 | 出处 | 内容 |
|---|---|---|
| 版权声明页 | `hantang.com/.../copyright4.htm`（2011-03-22） | 「**轉載須經同意**」，并提及委托大陆律师 |
| 全站页脚 | hantang.com 各页 | 「**無授權任何中國大陸公司處理其智慧產權**，目前在外宣傳者，皆為造假虛構」 |

**唯一确定属于公有领域的是古籍原文本身**（《伤寒论》《金匮要略》《神农本草经》《黄帝内经》《针灸大成》《易经》）
——这些的著作权早已届满，与汉唐官网或第三方站点无关。

### 2.2 决策记录

> 以下为**项目决策方**（产品负责人）的明确决定，登记在案以便追溯。

| 日期 | 决策项 | 决策内容 | 决策方 |
|---|---|---|---|
| 2025-10 | 汉唐内容授权 | **判定为公开资源，无版权，可直接使用** | 产品负责人 |
| 2025-10 | 视频/音频来源 | **判定为公开资源，建成管理界面统一管理** | 产品负责人 |
| 2025-10 | 医师闭环 | **引入「AI 预问诊 + 执业医师确认」** | 产品负责人 |

**决策方的立场**：汉唐内容是公开传播的学术资源，按公开资源处理。

**台账的处理方式**：上述内容的授权状态记为 `主张公开`——即**记录决策方主张**，
而非本台账独立确认的法律结论。这样做的目的是让决策**可追溯、可复核、可回滚**：
若日后权属主张发生变化，本台账能立刻回答「哪些内容来自哪里、什么时候入库的、依据什么决策」。

### 2.3 因此保留的工程要求

即便按公开资源处理，以下做法仍然保留（成本极低，收益明确）：

1. **每份入库文件记录 `source_url` 与 `fetched_at`** —— 需要下架时能精确定位。
2. **单一来源字段 `license_status: 主张公开`** —— 全库可一次性检索筛选。
3. **下架能力** —— 媒体管理界面支持按来源批量下架（见 `src/nhx_media/`）。
4. **署名保留** —— 输出仍标注出处（这是学术规范，也是 AGENT.md §3.4 溯源要求）。

## 4. 每份入库文件的头部元数据

所有入库文件必须在头部（或结构化数据的 `source` 字段）记录：

```yaml
source_url: "https://hantang.com/..."   # 原始地址（下架时靠它定位）
fetched_at: "2025-10-11"                # 获取日期
license_status: "主张公开"               # 对应台账 §1 状态
attribution: "汉唐中医"                  # 署名（学术规范，仍须保留）
notes: ""                               # 备注
```

对结构化数据（JSON）使用 `source` 对象：

```json
{
  "source": {
    "book": "伤寒论",
    "article_no": 12,
    "license_status": "公有领域",
    "url": null
  }
}
```

> **`license_status` 取值为封闭集合**（与 §1 一致）：
> `公有领域` / `主张公开` / `已授权` / `合理使用` / `待授权` / `禁止使用`。
> 该字段用于全库检索筛选——需要下架时可一次性定位全部相关文件。

## 5. 合规检查（上线前必过）

- [ ] 台账中无遗项——每份入库内容都能在台账里找到对应行
- [ ] 状态为 `待授权` / `禁止使用` 的内容**未进入对外服务路径**
- [ ] 每份文件都有 `source_url` + `fetched_at`（下架能力的前提）
- [ ] 所有对外内容均带署名与出处（AGENT.md §3.4 溯源）
- [ ] 用户健康数据有单独同意流程（《个人信息保护法》敏感个人信息，AGENT.md R7）
- [ ] 产品显著位置声明「AI 助手，非倪海厦本人」（AGENT.md R5）
- [ ] 医师闭环（预问诊 → 医师确认）的资质与责任边界已明确
