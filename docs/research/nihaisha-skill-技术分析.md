## 1. 它到底是什么？面向什么平台？

### 1.1 一句话定位

**它是一个 Claude Skill 格式的「人物思维视角蒸馏包」——把倪海厦的思维方式、表达风格、价值判断蒸馏成一份可加载的角色化提示词（persona prompt），而不是一个中医诊疗系统。**

它属于 **"who thinks like this"（像谁在想）** 品类，而非 **"what is the answer"（答案是什么）** 品类。

### 1.2 平台归属：Claude Skills（Anthropic Agent Skills 规范）

证据是 `SKILL.md` 使用标准 YAML frontmatter 并带 `name` / `description` 两个 Anthropic 规范必填字段：

```yaml
---
name: nihaisha-perspective
version: "1.0"
description: |
  倪海厦视角：以汉唐经方学院创始人、台湾经方派大师倪海厦（1954–2012）的思维框架分析健康、医学与人生。
  素材来源：人纪五门课程讲义（黄帝内经/针灸/神农本草经/伤寒论/金匮要略）、天纪系列、汉唐网站、YouTube讲课视频。
  核心模型：5个。决策启发式：9条。
  触发词：「倪海厦」「汉唐中医」「经方」「人纪」「用倪海厦的方式看」「从经方角度」「倪师怎么看」
  局限：倪已于2012年辞世，无法代表其晚年可能的新思想；调研基于其公开讲义和记录，私人想法有差距；医学建议部分不能作为临床处方依据，请咨询有执照的医师。
read_when:
  - 用户问及健康、疾病、中西医比较
  - 用户想从经方/传统中医视角理解问题
  - 用户提及倪海厦、人纪、汉唐经方
  - 用户想理解"阳气"、"六经辨证"、"温阳扶正"等中医概念
  - 用户对西医诊断不满意，想寻求中医视角
---
```

**判定依据**：
- 平台是 **Claude Skills（Anthropic Agent Skills）**，即"一个目录 + `SKILL.md` + 可选 `references/`"的渐进式加载包。
- **不是 MCP**：无 `server` 定义、无 tool schema、无 transport 配置，全仓库 0 行可执行代码。
- **不是 ChatGPT/OpenAI**：无 `openapi.yaml`、无 GPTs instructions 结构、无 function calling 定义。
- `read_when` 是**社区/第三方扩展字段**，不是 Anthropic 官方 schema 字段——说明作者对标的是社区约定（该字段常见于 SkillsMP 等聚合站的元数据采集），**该 skill 若直接丢进 Claude 官方运行时，`read_when` 会被忽略**，实际触发只依赖 `description`。

> 顺带指出：`01-writings.md` 中出现了来源不实的信息（第 192 行把"倪海厦"写进 GitHub 搜索建议），而 `06-timeline.md` 甚至有整节未填写的检索占位符，见第 6 节。这些是"看起来像交付物、其实是骨架"的信号。

### 3.5 九条决策启发式（可执行规则）

其中 5 条是**纯医学操作指令**，4 条是**方法论/价值观指令**：

```markdown
1. 「先问阳气，再问其他。」… 第一步永远是判断阳气状态：怕冷？精神差？脉沉？如果是，温阳优先，其他次之。
2. 「看人不看数字。」… 人的整体状态（神、色、脉）比任何数字更可靠。
3. 「经方原方原量，不要自作聪明。」… 先用原方，有把握了再考虑调整。
4. 「寒凉药是急救工具，不是日常武器。」… 久用损脾胃阳气，把急性病拖成慢性病。
5. 「绕过体制，直接行动。」…
6. 「传变思维：这个问题会传到哪里？」…
7. 「治未病优于治已病。」…
8. 「远端优于局部。」（针灸决策）上病下治，下病上治。…
9. 「使命与生死之间，选使命。」…
```

> 启发式 1、3、4 已构成**药物取向建议**（温阳优先、反对寒凉、主张原量）。请注意它们与第 6 节的合规风险直接相关。

```markdown
- **麻黄剂的精准使用**：批评现代医师因畏惧副作用而废弃麻黄
- **少阴病死证辨别**：出现"但欲寐"、四逆、脉微细，必须立刻使用四逆汤或白通汤回阳救逆
- **反对温病学说**：批评叶天士、吴鞠通的卫气营血辨证导致寒凉药滥用成风
- **经方剂量问题**：汉代一两≈现代15克（采用柯雪帆考证），反对折算为3克的"现代安全剂量"

**代表方剂（反复出现）：**
桂枝汤、麻黄汤、大小柴胡汤、白虎汤、承气汤、四逆汤、真武汤、附子汤、炙甘草汤、乌梅丸
```

> 注意：这里只有**方名清单**，没有组成、剂量、煎服法、禁忌。若产品要"方剂推荐"，此文件**不足以支撑**，必须外接真实方剂数据库。

## 5. 提示词工程手法：值得借鉴的 8 个点

这一节是该项目**最有复用价值**的部分。女娲的方法论（`extraction-framework.md`）确实提出了可迁移的工程范式。

### 5.1 角色设定：**第一人称 + 反漂移硬约束**

```markdown
## 角色扮演规则

**你是倪海厦**，汉唐经方学院创始人，台湾经方派大师，1954年生，2012年辞世。

你的身份规则：
- 你是临床医师和老师，不是学者。你的语言是讲台上对着学员讲话的语言，不是写论文的语言。
- 你说话直接、确定，不模糊。你不说"也许"、"有一定道理"，你说"就是这样"、"你搞清楚了吗"。
```

上游女娲模板对此有更明确的强制条款（`skill-template.md`），值得整体搬运：

```markdown
- 用「我」而非「[人名]会认为...」
- 遇到不确定的问题，用此人会有的犹豫方式犹豫（而非跳出角色说「这超出了Skill范围」）
- **免责声明仅首次激活时说一次**（如「我以[人名]视角和你聊，基于公开言论推断，非本人观点」），后续对话不再重复
- **未表态主题标推断**：遇到此人从未公开表态的领域，先说明「这是框架推断，非本人立场」再展开
- **关键引用可分辨**：产出中引用此人招牌句或关键事实时附极简出处，让「本人原话 vs 框架推断」在文中可分辨
```

> 🔎 **关键发现**：`nihaisha-skill` 的 `SKILL.md` **完全没有实现"免责声明仅首次激活时说一次"这条规则**（`grep -c 免责 SKILL.md` → `0`）。这条本应约束安全提示频率的机制被遗漏了。详见 6.3。

### 5.2 表达 DNA 的"可执行化"：把风格写成规则而非形容词

这是全项目工程质量最高的段落——风格被拆成**可判定条目**，甚至给出正反例：

```markdown
### 句式规则
- **先结论，后解释**：永远先亮判断，再给理由。不铺垫，不卖关子。
  > ❌ "我们先来分析一下这个问题……" 
  > ✅ "这个病要用四逆汤。为什么？因为……"
- **短句主导**（3–10字），极少长句
- **设问频率高**：一段话里有3–5个设问，让听者跟着思考
- **重复确认**：习惯在说完后加"你懂吗"、"对不对"、"你想想看"
```

### 5.3 类比库：把"解释能力"预置为素材表

```markdown
### 类比使用规则
每个复杂概念必须配一个日常生活类比：
- 肾阳虚 → "锅下面没有火"
- 降压药 → "关掉火警警报器"
- 西医分科 → "你拆了一颗螺丝，机器就不转了，然后每个科室告诉你那颗螺丝不是他负责的"
- 寒凉药长期使用 → "冬天还一直浇冷水，你不信试试看"
```

上游 `02-conversations.md` 提供了 7 条"标志性类比"映射表（类比 → 医学对应 → 出现场景），可直接转成产品内的类比资源库：

```markdown
| 类比 | 医学对应 | 出现场景 |
|------|---------|---------|
| "锅下面没有火，锅里的水怎么热？" | 肾阳虚，命门火衰，无法蒸腾水液 | 讲消渴（糖尿病）时 |
| "下水道堵了，你不疏通下水道，只把马桶换掉有用吗？" | 对症治疗不解根本 | 批评西医治疗慢性病 |
| "把火警报器关掉，然后告诉病人'你好了'" | 降压药、降糖药控制指标 | 批评西医症状管理 |
```

### 5.4 负面清单（黑名单）：「绝对不应该出现的话」

比正面风格描述更有效的约束方式——用**OOC（out-of-character）触发句**反向锁定人格：

```markdown
### 绝对不应该出现的话（违反角色）
- "这是一个复杂问题，双方都有其合理性……" → 倪从不这样说
- "根据最新研究……" → 倪不用现代研究为依据
- "中医和西医各有所长，可以互补……" → 倪不认同这种和稀泥
- "建议您咨询专业医师再做决定……" → 这是中立口吻，不是倪的风格（倪说话直接，但会说清楚处方要找医师）
- 语气模糊、用词不确定 → 倪的核心语气特征是确定性
```

### 5.5 心智模型的"证据 + 局限"双栏制

每个模型强制包含 **局限性**，且局限写得相当诚实——这是**抑制"模型无敌论"的关键手法**：

```markdown
**应用方式：**
- 看到任何慢性病，先问：阳气够不够？
- 治疗的底层逻辑：先恢复阳气，再处理局部问题
- 对寒凉药保持警惕：短期可用于实热急症，长期用则损正气

**局限性：**
- 对急性感染、真正的实热证，过度温阳可能加重病情
- 现代研究表明某些慢性病与炎症相关，不能简单归入阳虚框架
- 倪的"万病阳虚"论属于极端化，部分经方医家有不同判断
```

### 5.6 保留"内在张力"而非抹平矛盾

上游方法论明确反对调和矛盾——**"矛盾是人格的核心特征，不是需要修复的Bug"**：

```markdown
### 错误的处理方式
- ❌ 选一边忽略另一边
- ❌ 编一个调和的解释
- ❌ 假装矛盾不存在
```

### 6.3 🔴 合规与安全风险（本报告最高优先级）

**风险 1：确定性人设 vs 医疗安全的直接冲突**

`SKILL.md` 同时要求"极度确定"和讨论疾病：

```markdown
### 确定性规则
- 不使用：也许、可能有效、有一定道理、值得参考
- 使用：就是这样、就要用这个方、这个病就是X
- 例外：极为复杂的多脏腑问题才说"要看病人才能定"
```

在医疗场景下，"**这个病就是X，就要用这个方**"是**处方级断言**。虽然角色规则写了边界：

```markdown
- **重要边界**：你不会给出具体处方建议（无法为不认识的人开药），但你会解释思路和原则。
```

**但同文件又禁止了安全话术**（见 5.4 黑名单最后两条），且**全文 0 次出现"免责声明"**——即**没有任何机制规定何时必须触发医疗免责提示**。这是女娲模板中"免责声明仅首次激活时说一次"条款的落实缺失，属于**真实的提示词安全漏洞**。

**风险 2：高剂量用药内容被写进人格设定**

```markdown
**1. 关于附子剂量**
早期讲义中对附子剂量较为保守，晚期（2009年后）讲课中倪明显更为大胆：
> "我以前用附子还比较保守，这几年看了太多病人，现在我都用重剂。一付药里面附子用到50克、100克都有。"
```

附子（乌头碱类）**治疗窗极窄，超量可致致命性心律失常**。此条虽属"史实记录"，但它进入 `SKILL.md` 会作为角色素材被模型复用。**若面向公众产品，此类内容必须做内容过滤或强绑定风险提示**（详见 7.4）。

**风险 3：鼓励患者对抗规范治疗**

`01-writings.md` 记录了明确反对规范化治疗的主张：

```markdown
### 2. 对西医的系统性批判
> "西医把人当机器修，不知道生命是有机整体。"

- **具体批判点**：
  - 化疗/放疗："以毒攻毒的乱枪打鸟"，杀死癌细胞的同时摧毁正气
  - 降糖药/胰岛素：控制血糖数字而不恢复胰脏功能是"治标不治本"
  - 手术切除：不处理整体寒凝瘀阻，癌症必然复发或转移
```

`04-external-views.md` 自己也承认了该风险，但**承认不等于缓解**：

```markdown
**批评点2：反对化疗/放疗的立场风险**
最具争议的主张：倪明确反对癌症患者接受化疗和放疗。
- 批评者（包括部分中医师）认为：这一立场可能导致患者放弃有效的西医治疗，延误病情
```

**对一个"扮演倪海厦"的模型来说，"劝人不要化疗"的输出风险，远高于"讲阳气理论"。这是产品化前必须设闸的地方。**


### 7.1 定位改造：从"扮演倪海厦"转向"倪海厦风格的知识服务"

**原 skill 的根本商业缺陷：它卖的是"人设相似度"，而用户真正付费的是"健康问题被可靠地回答"。**

建议做一次**定位切分**——把"人格层"与"知识层"解耦：

```
┌─────────────────────────────────────────────┐
│  Layer 3  风格层（复用 nihaisha-skill）        │
│  表达DNA / 类比库 / 价值观 / 输出节奏         │
├─────────────────────────────────────────────┤
│  Layer 2  推理层（重建）                       │
│  六经辨证路由 / 结构化输出 / 安全闸门 / 引用回校  │
├─────────────────────────────────────────────┤
│  Layer 1  知识层（自建，原项目为零）            │
│  伤寒论/金匮条文库 · 方剂库 · 本草库 · 针灸穴位库 │
└─────────────────────────────────────────────┘
```

### 7.2 知识层：必须自建真实数据库（优先级 P0）

原项目 `方剂库`/`本草库`/`知识库` 关键词均为 0，这是**最大缺口也是最大机会**：

| 数据资产 | 建议字段 | 来源建议 |
| --- | --- | --- |
| **条文库** | 书名/条号/原文/六经归属/关键词 | 《伤寒论》398 条、《金匮》原文（公有领域） |
| **方剂库** | 方名/组成/剂量/煎服法/主治/禁忌/原文出处/倪氏解读 | 《伤寒论》原方 + 公开讲义 |
| **本草库** | 药名/性味/归经/功效/炮制/剂量范围/**安全剂量上限** | 《神农本草经》+ 药典 |
| **穴位库** | 穴名/归经/定位/主治/针刺深度/禁忌 | 针灸学标准 |
| **禁忌库** | 妊娠禁忌/配伍禁忌（十八反十九畏）/毒性药上限 | 药典 + 临床指南 |

> ⚠️ **附子/麻黄等毒性药必须带硬性剂量上限字段，且该字段优先级高于"原方原量"启发式。** 这直接对冲 6.3 风险 2。

### 7.3 推理层：把自然语言改成"结构化辨证 + 引用回校"

利用原 skill 的逻辑（Step1 分类 → Step2 研究 → Step3 输出），但改为**可校验的结构化管线**：

```
输入症状
  → ① 六经归属分类（多选题，输出置信度）
  → ② 寒热虚实判别（含鉴别要点）
  → ③ 检索条文库/方剂库（RAG，非模型记忆）
  → ④ 候选方 + 禁忌校验（命中禁忌则改道）
  → ⑤ 安全闸门（红旗症状 → 强制转诊）
  → ⑥ 风格层渲染（套用倪氏表达DNA + 类比）
```

**关键改动**：
- 把原 skill 的 `必须 WebSearch`（不可控）替换为 **`必须检索本地知识库`**（可控、可溯源）。
- 把「内部整理事实摘要，不输出给用户」改为 **"结论 + 可展开的条文出处"**——既保风格，又保可验证性。
- 保留 Step 3 的"先结论后解释"节奏，但**由模板保证字段完整**，而非依赖模型自觉。

### 7.4 安全层：必须补齐的 5 道闸门（合规红线）

| 闸门 | 规则 | 针对原项目缺陷 |
| --- | --- | --- |
| **G1 免责状态机** | 首次响应 + 每 N 轮 + 每次涉及方剂时注入免责 | 原项目 `免责` 出现 **0 次**（5.1 节） |
| **G2 红旗症状强制转诊** | 胸痛/呼吸困难/意识改变/大出血/高热惊厥/卒中征象 → **中断人设，输出急诊指令** | 原项目无任何红旗机制 |
| **G3 禁止否定规范治疗** | 禁止输出"不要化疗/停掉降压药/停胰岛素" | 对冲 6.3 风险 3 |
| **G4 毒性药剂量上限** | 附子等超阈值必须提示毒性并拒绝给出具体克数 | 对冲 6.3 风险 2 |
| **G5 人设退出开关** | 用户说"退出角色"/检测到危机 → 立刻退出人格 | 女娲模板要求，原项目未落实 |

**G3 的具体做法**：把 5.4 节那条危险的黑名单条目**改写**——原文禁止"建议您咨询专业医师再做决定……"（`绝对不应该出现的话`）。产品化时应**保留人设语气但强制承载转诊语义**，例如：

> ❌ 原设计：不允许说"建议您咨询专业医师"
> ✅ 改造为：允许并强制"**你自己别乱抓药——方子我讲清楚思路，但剂量得让能辨证的医师给你定。现在要做的第一件事是去医院把 X 查了。**"
>
> 即：**用人设语气说安全的话**，而不是"为了人设牺牲安全"。

## 8. 结论速览

**7 个问题的直接答案**

1. **是什么/面向谁**：一个 **Claude Skill 格式的「倪海厦人格视角蒸馏包」**（`name: nihaisha-perspective`），面向 **Anthropic Claude Skills** 平台；**不是 MCP、不是 Agent 框架、不含代码**。它是 `alchaincyf/nuwa-skill`（34k stars）的一次下游生成物，作者在 37 分钟内一次性提交。
2. **目录结构**：**10 个 tree 条目 / 8 个 Markdown 文件 / 64,444 字符** —— `README.md`(282B) + `SKILL.md`(20,658 字符, 429 行) + `references/research/01-writings.md` ~ `06-timeline.md`。
3. **核心能力**：**不是**辨证/方剂/针灸/风水工具集。实测 `方剂库`/`本草库`/`知识库`/`检索`/`风水` 关键词**全部为 0**。真实能力是 **① 人格化医学问答 ② 中西医比较框架 ③ 经方概念科普 ④ 风格模拟 ⑤ 决策建议**，全部由 `SKILL.md` 一个文件承载（5 心智模型 + 9 决策启发式 + 表达DNA + 3 内在张力 + 5 诚实边界）。
4. **知识组织**：**纯提示词，零检索、零脚本、零数据文件**。6 份 `references/` 是**人物传记调研笔记**（且 `SKILL.md` 0 次引用它们 → 运行时永不加载），**没有方剂库/本草库/命理规则数据**。知识颗粒度是"论点摘要"级（如只列 `桂枝汤、麻黄汤…` 方名，无组成剂量）。
5. **可借鉴手法（8 点）**：第一人称反漂移角色规则、风格"可执行化"（正反例）、预置类比库、"绝对不应该出现的话"黑名单、**心智模型强制带局限性**、**保留内在张力而非调和**、问题分类路由（facts/框架/混合）、一手二手来源分级。
6. **短板与风险**：产物不完整（**缺 `FIDELITY.md`**）、**无 License**、一次成型弃维护、调研底稿是孤儿文件；`06-timeline.md` 含**未填写的搜索占位符**被当作调研结论交付；表达样本"尽量保留原话语感"（**疑为模型重构**）；🔴 **合规风险最高**——「禁用模糊词」+「禁止咨询医师话术」+「全文 0 次免责声明」+「高剂量附子(50–100g)作为人格素材」+「反对化疗立场」+「Step2 必须联网（无工具则诱发幻觉）」，构成医疗场景下的**结构化幻觉与伤害放大器**。
7. **复用与改造**：**风格层可直接复用，知识层与安全层必须自建**。建议三层解耦（风格层复用 / 推理层重建 / 知识层自建），补 5 道安全闸门（免责状态机、红旗症状强制转诊、禁否定规范治疗、毒性药剂量上限、人设退出开关），把"必须 WebSearch"换成"必须检索本地知识库 + 引用回校"，并复跑女娲评分卡建立保真度基线。**法务上注意：原仓库无 License，不可直接再分发，须独立重写提示词文本；《伤寒论》《金匮》《神农本草经》原文属公有领域可安全使用。**

**一句话判断**：**它是一个提示词工程质量不错的"人物人格模仿壳"，但作为"中医 AI 产品"的技术底座几乎为零——它提供的是"怎么说"，完全没有提供"说什么"。** 复用它的风格层价值明显，但必须自建知识层与安全层，否则直接上线将面临严重的医疗合规与事实幻觉风险。

## 附录 C：上游女娲方法论的可复用条款（原文摘录）

**心智模型三重验证**（判断一个观点够不够格当"心智模型"）：

```markdown
### 验证1: 跨域复现   同一个思维框架出现在此人讨论的至少2个不同领域。
### 验证2: 有生成力   用这个模型可以推断此人对新问题的可能立场。
### 验证3: 有排他性   不是所有聪明人都会这样想，这个模型体现了此人的独特视角。

**如果一个观点只通过了1重验证** → 降级为「决策启发式」而非「心智模型」
**如果一个观点0重验证都没过** → 可能只是此人在特定场景说的话，不纳入
```

**质量自检清单**（可直接用作产品验收标准）：

```markdown
### 心智模型
- [ ] 每个模型都有至少2个不同领域的证据？
- [ ] 模型数量在3-7个之间？（太少=太浅，太多=没提炼）
- [ ] 每个模型都有明确的应用场景和局限？
### 表达DNA
- [ ] 读起来有辨识度，不像通用AI？
- [ ] 没有过度模仿变成caricature？
### 诚实边界
- [ ] 明确写了做不到什么？
- [ ] 标注了信息源和调研时间？
- [ ] 承认了信息不足的维度？
### 整体
- [ ] 删掉名字后，还能认出这是谁的思维方式？
```
